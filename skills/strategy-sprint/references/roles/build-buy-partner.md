# Build / Buy / Partner

**Stage:** Decide · **Role 12 of 24** · **Output:** `strategy-output/12-build-buy-partner.md`

## Job

Compare building, buying (vendor or acquisition), partnering and waiting for a capability, on time to value, total cost, control, risk and strategic fit.

## Use when

- An option depends on a capability the company does not have yet.
- Vendors are pitching and the team is unsure whether to build.

## Skip when

- The capability is commodity with no strategic role; recommend buying and say why.

## Needs (named, versioned inputs)

- Capability definition
- AI feasibility findings (if AI)
- Vendor information from approved sources

## Method

1. Define the capability and its strategic role: differentiator, enabler or commodity.
2. For each path (build, buy, partner, wait): time to first value, 3-year total cost range, control of data and roadmap, switching cost, talent need, key risks.
3. Name the conditions under which each path wins.
4. For buy and partner, list due-diligence questions; do not contact vendors without approval.
5. Recommend a path per option as `[INFERENCE]`, with the switch-over trigger (for example, "buy now, build when volume exceeds X").

## Output sections

- Capability role
- Path comparison table with ranges
- Conditions each path wins
- Due-diligence questions
- Recommended path and switch trigger
- Handoff block (`assets/templates/handoff.md`)

## Checks before handoff

- [ ] Costs cover the full period, including integration and exit.
- [ ] Data ownership is explicit.
- [ ] Every material claim labeled per `references/operating-rules.md`

## Stop and escalate if

- Vendor claims are the only evidence for a load-bearing assumption.
- Any action outside the read-only default is needed.
